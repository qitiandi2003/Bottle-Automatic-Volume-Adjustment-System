# 待验证与后续工作

- [ ] 在实际部署环境执行 `pip install -e .`，确认 `bvc-run`、`bvc-capture`、`bvc-collect` 与系统服务使用同一个 Python 环境。
- [ ] 为系统服务设置绝对路径 `BVC_DATA_DIR`，确认日志、录像和图片目录可写，重启后仍定位到同一数据目录。
- [ ] 在目标设备安装相机 SDK，联调真实相机、像素格式转换、断连恢复和关停时的资源释放。
- [ ] 与上位机验证启动、暂停、停止、刻度锁定和注液完成的协议时序。
- [ ] 使用透明瓶、棕色瓶及不同光照的同一批样本验证检测参数，评估误检、漏检和注液偏差后再调整阈值。
- [ ] 在目标设备测量每阶段耗时、整帧延迟和 CPU 占用；性能结论同时记录设备、分辨率和测试场景。
- [ ] 实机验证 HTTP 关闭时的本地录像、ffmpeg 转码、长时间运行的空间清理和异常退出后的源帧保留。
- [ ] 仅在需要时更新 `docs/legacy/scripts/` 中依赖旧 Detector 的流测试入口，改用当前包和状态机；旧资料继续按历史用途保留。
- [ ] 将 `tests/manual/` 的现场样本和联调步骤整理为可复现说明，明确各脚本的相机、网络和图片输入要求。
- [ ] 代码、配置和协议变化时同步维护 README、配置说明及相关注释，并补充可复现的回归测试。

设备地址、账号、密钥和部署目录由本地环境变量配置，不在仓库中保存登录凭据。
