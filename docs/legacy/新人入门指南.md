# 新人入門指南 — auto_volume_control

> 對象: 新接手的負責人, Python 熟, OpenCV 初級~中級
> 目標: 1~2 天跑通、讀懂算法主幹、能照貓畫虎改一個檢測器
> 本文不重複架構全景, 僅給戰術層手冊. 架構/診斷另見 `docs/项目全景.md`

---

## 1. 這是什麼項目

用一台 2048×3072 海康威視相機, 盯住一根試管. 當液體注入試管時, 實時輸出兩個數:
- **gap** — 刻度線相對於圖像中心的水平偏移 (整數, 像素)
- **l2s** — 液面前沿距刻度線的水平距離 (整數, 像素, 越小說明離目標越近)

結果通過 TCP 發給上位機, 上位機據此控制機械臂的泵, 液面到目標刻度就停泵. 核心是 OpenCV 的 Sobel 梯度 + OTSU 二值化 + 一小堆狀態機, **沒有深度學習**, 一台普通 PC 就能實時跑.

本倉庫還有一個獨立的 `detect_liquid_level.py`, 用的是 Canny + Hough 管壁檢測那一路, 僅供離線驗證/對照, 不進主循環.

## 3. 首次啟動與停止

### 3.1 正常啟動

```bash
source .venv/bin/activate
python main.py
```

`main.py` 只有 37 行, 調用序列如下 (main.py:16-37):

1. `OpenCamera()` — 枚舉設備→創建句柄→開取流→若 `EXP_BOOT_ENABLED=True` (默認), 按 `EXP_BOOT_US=12000us` 設手動曝光
2. `Detector(cam)` — 建檢測器實例 (默認 `DEBUG_MODE=False`)
3. `detector.start()` — 啟動後台線程, 開始抓幀/處理
4. `press_any_key_exit()` — 主線程阻塞在這裡, 等你按任意鍵
5. 按鍵後依次 `detector.stop()` → `CloseCamera(cam)` → `cv2.destroyAllWindows()`

### 3.2 停止方式

**按鍵盤任意鍵** — `rt_util.py` 的 `press_any_key_exit()` 讀 stdin 一個字符就返回. 不能用 Ctrl+C 正常退出 (沒裝 SIGINT handler, 會留下殭屍進程和沒釋放的相機句柄).

如果忘了按鍵直接 Ctrl+C, 下次啟動可能報 "相機已被佔用". 殺 python 進程後再開.

補註: `main.py` 沒包 `finally`, 只有 `try/except`, 但 `detector.stop()` / `CloseCamera` 寫在 `except` 外, 即使 try 內部 raise 後控制流走到 except 打印錯誤, 最後這段清理仍會執行. 所以只要不是 SIGKILL 之類的硬殺, 資源大體能釋放.

### 3.3 常見坑

| 現象 | 原因 | 解決 |
|---|---|---|
| `[Main Error] 无法启动工作线程` | 相機沒插 / 沒打開 / 被別人佔用 | 插相機, 關掉 MVS 工具 |
| `ConnectionRefusedError: 9001` 刷屏 | TCP 發送端口沒人接 | `export TX_ENABLED=0` 關掉發送, 或啟動上位機模擬器 `python tests/test_tcp_cmd.py` |
| 黑屏 / 全白 | 曝光過低/過高 | 改 `EXP_BOOT_US` (默認 12000 us), 或等首次試管檢測後自動曝光生效 |
| `ImportError: MvCameraControl_class` | MvImport 路徑沒找到 | 檢查 `rt_config.py:6-19`, 確認 `MvImport/` 目錄還在 |
| 窗口狂刷但沒 l2s | 試管沒檢測到 / 刻度線不穩 | 讓試管穩定 10 秒 (見 `STABLE_WINDOW_S`), 或關掉發送直接看日誌 |

### 3.4 關閉 TCP 發送離線跑

開發調試多數情況不用發包, 推薦:

```bash
export TX_ENABLED=0
export SHOW_WINDOWS=1     # 如果有顯示器
python main.py
```

## 5. 核心算法解讀 (B 算法級, 重點章節)

主循環 (`Detector.run()`) 每幀二選一:
- **未鎖定模式** (`_process_scale_detect`, detector.py:988-1137) — 還沒穩定鎖到刻度線, 持續檢測試管邊界 + 刻度線, 累計穩定性
- **鎖定模式** (`_process_locked_mode`, detector.py:759-986) — 刻度線已穩定 10s+, 凍結 x 座標, 改做液面追蹤

切換條件: `gap_stability.py` 判斷 10 秒內刻度間隙波動 ≤15px 且至少 3 個樣本 → 進入鎖定.

### 5.1 detector.py 主循環狀態機

**OpenCV 操作鏈 (未鎖定模式)** — 每幀做這些, 本質是"找試管和刻度":
1. 從相機抓一幀 BGR (camera_io)
2. `SlewTubeTracker.update()` 跟蹤試管上下邊界 — 內部用 Hough 直線 + slew rate 限制邊界每幀最多移動 10px, 防抖
3. `find_center_scale_line()` 在試管內部水平搜索一條最強的垂直邊緣線 — `cvtColor→CLAHE→GaussianBlur(3×3)→Sobel(CV_16S, dx=1, ksize=3)→convertScaleAbs→列和→帶中心懲罰的 argmax`
4. 拿到 `x_scale` 後, 塞進 `GapStability.update(time, gap)`, 計算 `gap = x_scale - image_width/2`
5. 時間窗口穩定 → 進入鎖定模式, `locked_gap_val` 凍結

**OpenCV 操作鏈 (鎖定模式)** — 每幀做這些, 本質是"追液面":
1. 第一幀 (切換瞬間): `calibrate_first_frame()` 建基準, 記下 `scale_line_x` / `detection_start_x` / `sobel_proj_base`
2. 後續幀: 調整曝光維持亮度 — 當前灰度中位數與首幀相差 >5 → 按比例重設曝光, 夾鉗 [3000, 40000] us (detector.py:841)
3. `detect_liquid_level_by_histogram()` — 在刻度線左側 ROI 做 `GaussianBlur(15×15) → Sobel(CV_32F, dx=1, ksize=5) → |sobel| 列均值 → 減首幀基準 → 平滑 → 找峰`, 取最左峰為液面
4. 單調約束: 液面只能向左移動 (即 x 只能變小), 反向跳變認為是雜訊
5. 輸出 `l2s = liquid_max_x - scale_line_x`, 若波動 <10px 且距刻度 ≥60px, 置 10000 (無效); 判定邏輯在 detector.py:878 `amp >= delta_thr or distance < 60` 的反向

**3+ 個關鍵 magic number**:

| 位置 | 值 | 語義 / 改它會怎樣 |
|---|---|---|
| detector.py:57 `STABLE_WINDOW_S` | 10.0 | 刻度線需穩定這麼多秒才進鎖定. 調小→更快進入檢測但抗抖差; 調大→更慢響應 |
| detector.py:58 `STABLE_SPAN_PX` | 15 | 窗口內最大間隙波動. 調小→更嚴, 抖一下就重來; 調大→容忍更大擺動 |
| detector.py:63 `LIQ_LOCKED_MAXX_DELTA_MIN` | 10 | 鎖定模式液面 x 的波動阈值. 窗口內波動 <10px 且遠離刻度就不輸出 — 防止假檢測觸發停泵 |
| detector.py:668 `if abs(l2s_det) <= 11` | 11 | 液面距刻度 ≤11px 視為完成 (發 STATUS_COMPLETED) |
| detector.py:882 `if self.l2s_disp <= 16` | 16 | 鎖定模式另一處到達判定, 比 11 寬鬆, 用於觸發 `is_reached` 走完成流程 |

**2+ 個調優切入點**:
1. **刻度抖動太敏感** — 提升 `STABLE_SPAN_PX` 到 20~30, 或 `STABLE_MIN_SAMPLES` 到 5~10, 讓穩定性判定更寬容
2. **液面波動過濾太狠** — `L2S_JUMP_LOW=36` / `L2S_JUMP_HIGH=100` (rt_config.py:76-82) 是跳變過濾閾值, 小值→高值的跨越被當作越界停泵觸發. 液體表面有泡沫時可以放寬

### 5.2 center_scale.py 試管+刻度定位

這個文件乾兩件事: (a) 試管在圖像哪個水平範圍 (b) 刻度線在哪個 x.

**試管檢測 (`SlewTubeTracker.update`, center_scale.py:304)** — 薄皮包裝:
- 底層調 `tube.py:detect_tube_hough_grad()` — 這個是 Hough 直線加垂直梯度找上下邊界
- 包裝層做兩件事:
  1. **slew 限制** (center_scale.py:350-358): 相比上一幀, 左邊界只能向內縮 ≤10px, 右邊界只能向內縮 ≤10px. 防止邊界突然跳
  2. **update_every** 頻率控制 (center_scale.py:306): 可以 N 幀做一次 Hough, 中間用緩存. 當前默認每幀都做

**刻度檢測 (`find_center_scale_line`, center_scale.py:563)** — OpenCV 操作鏈白話:
```
cvtColor(BGR→GRAY)           # 灰度化
_clahe_gray(...)              # CLAHE 自適應亮度均衡, 對抗強光/逆光
GaussianBlur(3×3)             # 輕微平滑去椒鹽雜訊
Sobel(CV_16S, dx=1, ksize=3)  # 只要垂直邊緣 (刻度線是豎線)
convertScaleAbs(...)          # 取絕對值, 正負邊緣都留
roi = gx[y0:y1, cx-band:cx+band]   # 裁到試管中央 ±50px
col_sum = roi.sum(axis=0)           # 列方向求和 — 刻度線那列和最大
score = col_sum - λ * |x - cx|     # 加中心懲罰, 離圖像中心越遠扣分
best_x = argmax(score)              # 挑分最高的列
# 置信度 = 該列上超過 0.6*Otsu 閾值的像素比例
```

為什麼加中心懲罰 (`lambda_center=1.0`)? 試管內部常有其他豎線 (比如反光、液面弧線邊緣), 不加懲罰會抓錯. 實際場景刻度線基本就在圖像中線附近.

**3+ 個關鍵 magic number**:

| 位置 | 值 | 語義 / 改它會怎樣 |
|---|---|---|
| center_scale.py:584 `band=50` | 50 | 刻度搜索帶寬 ±50px. 太小→刻度偏一點就找不到; 太大→容易被雜線干擾 |
| center_scale.py:610 `lambda_center=1.0` | 1.0 | 中心懲罰係數. 調到 0→純看邊緣強度, 容易跑偏; 調大→強制貼中心, 刻度實際偏心時會找錯 |
| center_scale.py:621-622 `thr=max(10.0, 0.6*t)` | 0.6×Otsu | 置信度判定閾值. 0.6 是經驗係數, 用來過濾弱邊緣 |
| center_scale.py:436-437 `top_frac=0.40, bot_frac=0.60` | 0.40/0.60 | 行檢測器排除試管中央 40~60% 的行 — 避免把液面誤認為試管上下邊界 |
| center_scale.py:264 `y_low=0.30, y_high=0.90` | 0.30/0.90 | 試管檢測窗口, 圖像垂直方向 30%~90%. 改窄→更快但容易切掉; 改寬→更慢, 容易把上方機械臂當作試管邊 |

**2+ 個調優切入點**:
1. **試管窗口漂移** (用一段時間邊界越縮越窄) — 檢查 `left_inc_max=10, right_dec_max=10` (center_scale.py:265-266 slew limit), slew 不對稱是這個現象根因. 需要的話改成對稱的 `±5`
2. **刻度線被反光誤定位** — 減小 `band` (50→30) 縮窄搜索範圍, 或提高 `lambda_center` (1.0→2.0) 強化中心約束

### 5.3 li_det.py 液面檢測 (鎖定模式主戰場)

**整體思路**: 液面是水平的亮→暗過渡帶, 在垂直的試管裡看起來就是一條豎直線 (沿 y 方向延伸的亮度突變). 對整個 ROI 做垂直方向列投影, 峰就是液面位置.

**首幀校準 (`calibrate_first_frame`, li_det.py:379)** — 建立"空試管"基準:
```
preprocess_image(img):                         # 預處理管道
  img[:,:,1]                                    # 綠色通道 (B=0,G=1,R=2 in BGR)
                                                #   為什麼是綠色? 液體多為藍/紅, 綠通道對比最穩
  medianBlur(15)                                # 15×15 中值, 消除椒鹽
  CLAHE(clip=2.0, tileGrid=8×8)                 # 分塊自適應對比度, 防強光過曝
  Sobel(CV_16S, dx=1, ksize=3) → convertScaleAbs # 垂直邊緣
  取反, Otsu 閾值化                               # 邊強的地方 = 黑
  AND 上 gray 本身的 Otsu                         # 兩個條件都強才保留
  medianBlur(7) → erode(3×3, 1次)                # 去毛刺 + 收縮
  ROI[500:1500, 500:1900] 做 80×1 開運算        # 去水平連通
# 基準 ROI 的 sobel 垂直投影存進 res['sobel_proj_base']
```

注意幾個硬編碼:
- `img[:,:,1]` 綠色通道 (li_det.py:20)
- `[500:1500, 500:1900]` 硬編坐標 (li_det.py:44) — 針對 2048×3072 試管一般出現位置, 換分辨率就炸

**檢測主函數 (`detect_liquid_level_by_histogram`, li_det.py:474)** — 逐幀做的事:
```
blurred = GaussianBlur(img[:,:,1], 15×15)        # 強平滑
roi_center = blurred[y1c:y2c, x1:x2]              # 中央 ROI, 上下各扣掉 max(5, h/5)
sobel_x = Sobel(roi_center, CV_32F, dx=1, ksize=5) # 大核 Sobel
sobel_proj = mean(|sobel_x|, axis=0)              # 列方向絕對值均值
edge_diff = clip(sobel_proj - sobel_proj_base, 0, None)  # 減去空試管基準, 只剩新增邊緣
edge_smooth = convolve(edge_diff, np.ones(21)/21, 'same') # 21 點箱平均
peaks = _find_edge_peaks(edge_smooth, h=50, dist=30, prom=30)
front_col = peaks[0]                              # 最左峰
liquid_max_x = x1 + front_col                     # 映回全圖坐標
```

為什麼這樣做?
- **GaussianBlur 用 15×15 大核** — 液面的亮度過渡是漸進的, 小核會把過渡帶本身當多個邊緣. 大核把它融成一條明顯的邊
- **Sobel ksize=5 而不是 3** — 同理, 強化過渡帶本身, 削弱噪點
- **減首幀基準** — 空管裡的刻度線、管口接縫、試管紋路也會產生邊緣. 首幀是空管, 做差就只剩液面
- **取最左峰** — 液體從右側注入, 液面在縮小 (left direction), 最左邊的新邊緣就是當前液面前沿

**3+ 個關鍵 magic number**:

| 位置 | 值 | 語義 / 改它會怎樣 |
|---|---|---|
| li_det.py:20 `img[:,:,1]` | 綠通道 | 為什麼綠: 中國常見試劑多為藍紫紅, 綠通道對比最穩. 換透明試劑/棕色試劑可能要換通道 |
| li_det.py:514 `GaussianBlur((15,15))` | 15×15 | 過渡帶平滑核. 液面薄 (~5px 過渡) 時減小到 9×9; 液面厚 (氣泡多) 時增大到 21×21 |
| li_det.py:524 `Sobel(..., ksize=5)` | 5 | Sobel 核大小. Sobel 核應與高斯核大致匹配, 否則 15×15 高斯模糊出來的寬過渡帶會被 3 核 Sobel 當作寬邊緣而削弱 (或被 7 核 Sobel 當成雙邊). 5 配 15 高斯正好; 如果高斯核改了, 這個也跟著動 |
| li_det.py:539 `height_thr=50, min_distance=30, prominence_thr=30` | 50/30/30 | 峰檢測三參數. height→峰最小高度, distance→兩峰最小距, prominence→峰相對谷的突出度. 峰丟失時降 height; 峰太多時升 prominence |

**2+ 個調優切入點**:
1. **液面未進入檢測區** (`status_msg` 一直說 no_peaks) — 降 `height_thr` (50→30), 液面比較淡時 edge_diff 的峰也會淡
2. **液面跳來跳去** (峰的位置每幀飄) — 升 `prominence_thr` (30→60) 濾掉小突起, 或增大平滑核 `ks=21→41`
3. **綠通道不合適** — 改 `img[:,:,1]` 為 `[:,:,0]` (藍) 或 `[:,:,2]` (紅). 測試方法: 拿首幀, `plt.imshow` 三個通道看哪個液面最清

### 5.4 detect_liquid_level.py 獨立測試管道 (Hough 路線, 與 5.3 對比)

這是另一套完全獨立的管道, **不進主循環**, 放這裡主要是離線驗證 + 對照算法. 寫法風格和 5.3 差別很大, 值得一讀.

**整體流程**:
```
imread(image_path)                             # 只接文件路徑, 離線用
cvtColor(BGR→GRAY)
GaussianBlur(5×5) → Canny(30, 100)             # 先 Canny, 不是 Sobel
HoughLinesP(threshold=150, minLen=w/4, gap=30) # 找水平長直線 = 管壁
angle < 10° 過濾出水平線
_cluster_values(threshold=20) 聚類             # 近似位置的線合併
tube_top, tube_bottom = centers[0], centers[-1]

# 粗定位弯月面 (列亮度梯度)
tube_roi = gray[tube_top:tube_bottom, :]
GaussianBlur(5×5)
col_brightness = mean(..., axis=0)              # 每列平均亮度
kernel = ones(15)/15, convolve 'same'           # 15 點移動平均
col_gradient = np.gradient(col_smooth)          # 1 階導
meniscus_x = argmax(|gradient|) in search_l..r  # 最大梯度位置 = 液面

# 精提液面 (逐行)
在 meniscus_x ± 60 內, 每行找梯度峰, > 2 保留
median + 15px 離群過濾
最上的點 = 液面線 y 最小

# 定位刻度 (類似但屏蔽弯月面附近 ±40)
col_masked = ...
閾值 = median + std
局部極大 (上下左右 2px 都小於自己)
_cluster_values(threshold=20)

# 讀數外推
reading = -(scale_marks[0] - meniscus_x) / interval
```

**與 5.3 (li_det) 的核心差異**:

| 對比項 | detect_liquid_level.py | li_det.py |
|---|---|---|
| 管壁檢測 | Canny + HoughLinesP | 不做 — 靠 center_scale 提供的 y0/y1 |
| 液面檢測 | 列亮度梯度 (1 階導) | Sobel (邊緣) + 減基準 |
| 基準 | 無 (每幀獨立) | 首幀 sobel_proj_base |
| 用途 | 離線驗證, 單張圖 | 實時, 進主循環 |
| 輸出 | PNG 可視化 | (x, y) 座標 + status msg |

**什麼時候用這個檔?**
- 收到一張奇怪的圖, 想看看不同算法誰更準 — 用它做對照
- 調查主算法漏檢時, 可以跑這個看"另一條路"能否檢到
- 做報告或 PPT 可視化

**3+ 個關鍵 magic number**:

| 位置 | 值 | 語義 / 改它會怎樣 |
|---|---|---|
| detect_liquid_level.py:23 `Canny(30, 100)` | 30/100 | Canny 雙閾值. 低→更多邊 (假陽性多); 高→更少邊 (漏檢多). 3:1 比例是經驗 |
| detect_liquid_level.py:24 `HoughLinesP(thresh=150, minLen=w/4, gap=30)` | 150/w/4/30 | 投票數 150→強線才算; minLen w/4 ≈ 750px→管壁通常跨過四分之一圖寬; gap=30 最大斷點 |
| detect_liquid_level.py:37 `_cluster_values(threshold=20)` | 20 | 把 y 差 ≤20 的線合併. 太小→碎片管壁出現多條; 太大→上下邊界合成一條 |
| detect_liquid_level.py:59-60 `search_l=0.30w, search_r=0.80w` | 30%/80% | 弯月面粗搜索範圍. 和 5.3 的鎖定模式 ROI 不是一碼事, 這個是完整圖寬百分比 |
| detect_liquid_level.py:86 `keep = |x_vals - x_med| < 15` | 15 | 逐行離群閾值. 液面有泡沫時可能要放到 25~30 |

**2+ 個調優切入點**:
1. **HoughLinesP 檢不到管壁** → `tube_top, tube_bottom = 0.3h, 0.65h` 兜底 — 想避免這個就降 `threshold=150` 到 100, 或 `minLineLength=w//4` 到 `w//6`
2. **離線批量調試** → 改 `main` 塊路徑: `li_det.py:767` 硬編碼 `folder_path`, `main` 入口在 `li_det.py:864-865`; `detect_liquid_level.py:222-223` 是 `main + 硬編碼路徑`. 批量跑一個目錄的所有 .jpg 看可視化輸出

## 7. 識別邏輯如何修改 (兩場景)

### 7.1 換試管規格/液體顏色: 閾值調參

假設來了一個新場景: 試管更細 (管徑縮小 30%), 液體是淺黃色. 跑起來發現 `STATUS_COMPLETED` 觸發得早了 10 秒, 液面明明還沒到刻度.

**步驟**:

1. **先看日誌看到什麼**
   ```bash
   tail -f logs/log_$(date +%Y%m)_*.txt
   ```
   關注這幾類訊息:
   - `液面-锁定发送: 状态=... 间隙=... 液面距刻度=...` — 每幀都發的心跳
   - `阶段1-未进入检测区` / `阶段2-...` / `阶段3-已到达` — li_det 內部狀態 (li_det.py:546, 569 等)
   - `液面距离刻度线小于16px，认为已到达刻度线` (detector.py:884) — 這條出現說明 `LIQ_LOCKED_MAXX_DELTA_MIN` 或 `l2s_disp <= 16` 被觸發

2. **定位是哪個參數提前觸發**
   如果日誌裡 `l2s_disp` 從 200 直接跳到 0, 說明是 detector.py:882 那個 `<=16` 把你打死了. 如果 `front_col` 一直很小, 那是 li_det.py:564 `reached_thr` 的問題 (`max(5, n//20)` 在 ROI 變窄時門檻也變窄).

3. **改參數**
   - 在 li_det.py 加實驗: 臨時把 `reached_thr = max(5, n//20)` 改成 `max(5, n//10)` — 門檻提一倍, 驗證是不是 ROI 變窄的鍋
   - 若是 `<=16` 誤觸, 改 `detector.py:882` 到 `<=8` (注意這是寫死的常數, 沒暴露成配置, 是坑)

4. **淺黃液體的特殊處理**
   淺黃和綠的分離度低, `img[:,:,1]` 綠通道可能看不清. 用 matplotlib 畫一下:
   ```python
   img = cv2.imread('one_frame.png')
   import matplotlib.pyplot as plt
   fig, ax = plt.subplots(1, 3)
   ax[0].imshow(img[:,:,0], cmap='gray'); ax[0].set_title('B')
   ax[1].imshow(img[:,:,1], cmap='gray'); ax[1].set_title('G')
   ax[2].imshow(img[:,:,2], cmap='gray'); ax[2].set_title('R')
   plt.show()
   ```
   選對比最強的通道, 把 `li_det.py:20, 514` 的 `[:,:,1]` 改成對應索引.

5. **驗證閉環**
   - 跑 10 組試管, 記錄每次 `is_reached` 觸發時的 `l2s_disp` 值
   - 用 `collect_debug_data.py` 把 `save_images/` 收起來
   - 看 `first_frame_img.png` 和 `first_enter_img.png`, 確認刻度線和液面位置合理

**center_scale 這邊順便看一眼**: `top_frac=0.40, bot_frac=0.60` (center_scale.py:436-437) 是行檢測器排除中央的比例. 試管更細但更短時, 可能要改成 `0.35/0.65` 讓檢測區更寬.

### 7.2 新增檢測對象 (以「氣泡檢測」為例)

假設要新加一個功能: 檢測試管內是否有氣泡, 發新狀態給上位機.

**步驟**:

1. **新建 `bubble_det.py` 放檢測邏輯**
   仿 `li_det.py` 的接口風格, 文件頂部放一個類似 `calibrate_first_frame()` 的初始化 (建立"無氣泡"基準), 再放一個 `detect_bubbles()` 主檢測.
   ```python
   # bubble_det.py (骨架示例, 實際要填 OpenCV 邏輯)
   import cv2
   import numpy as np

   def calibrate_bubble_baseline(img, tube_bounds):
       """首幀建無氣泡基準: 試管內部灰度均值/方差"""
       y0, y1, x0, x1 = tube_bounds
       roi = cv2.cvtColor(img[y0:y1, x0:x1], cv2.COLOR_BGR2GRAY)
       return {'mean': float(np.mean(roi)), 'std': float(np.std(roi))}

   def detect_bubbles(img, tube_bounds, baseline, thr_std_ratio=2.0):
       """
       氣泡特徵: 局部高方差 + 圓形. 用 HoughCircles 或自適應閾值做.
       返回 {'has_bubble': bool, 'count': int, 'positions': [(x,y,r), ...]}
       """
       y0, y1, x0, x1 = tube_bounds
       roi = cv2.cvtColor(img[y0:y1, x0:x1], cv2.COLOR_BGR2GRAY)
       roi_blur = cv2.medianBlur(roi, 5)
       circles = cv2.HoughCircles(
           roi_blur, cv2.HOUGH_GRADIENT, dp=1.5, minDist=20,
           param1=100, param2=30, minRadius=5, maxRadius=30)
       if circles is None:
           return {'has_bubble': False, 'count': 0, 'positions': []}
       positions = [(int(c[0]+x0), int(c[1]+y0), int(c[2])) for c in circles[0]]
       return {'has_bubble': True, 'count': len(positions), 'positions': positions}
   ```

2. **在 `rt_config.py` 加配置**
   ```python
   BUBBLE_DET_ENABLED = rt_util._env_flag('BUBBLE_DET_ENABLED', default=False)
   BUBBLE_THR_STD_RATIO = float(os.getenv('BUBBLE_THR_STD_RATIO', '2.0'))
   ```

3. **在 `detector.py` 插 hook**
   選鎖定模式的主循環作為插入點 (detector.py:759 附近的 `_process_locked_mode`):
   ```python
   # detector.py 頂部 import
   from bubble_det import calibrate_bubble_baseline, detect_bubbles

   # Detector.__init__ 增加
   self.bubble_baseline = None
   self.bubble_last_result = None

   # _process_locked_mode 裡, 首幀分支加 (仿照 first_frame_brightness 那段):
   if self.first_frame:
       # ... 現有 calibrate_first_frame ...
       if rt_config.BUBBLE_DET_ENABLED:
           tube_bounds = (state.y0, state.y1,
                          self.res['scale_line_x'], self.res['detection_start_x'])
           self.bubble_baseline = calibrate_bubble_baseline(bgr_image, tube_bounds)

   # 後續幀 detect_liquid_level_by_histogram 之後加:
   if rt_config.BUBBLE_DET_ENABLED and self.bubble_baseline is not None:
       tube_bounds = (state.y0, state.y1,
                      self.res['scale_line_x'], self.res['detection_start_x'])
       self.bubble_last_result = detect_bubbles(
           bgr_image, tube_bounds, self.bubble_baseline,
           thr_std_ratio=rt_config.BUBBLE_THR_STD_RATIO)
       if self.bubble_last_result['has_bubble']:
           self.logger.info(f"氣泡 {self.bubble_last_result['count']} 個")
   ```

4. **協議加新狀態 (如果需要上位機知道)**
   現有發送協議在 `rt_util.py:107-119` 的 `send_detect_packet()`, 是 8 字節 cpp 布局 (0xAA/status/gap_h/gap_l/l2s_h/l2s_l/0x55/0x00) 或 7 字節 std 布局; `control_channel.py:131-145` 是**接收**控制幀 (15 字節, struct.unpack 解析 height/scale_height/volume), 不是發送 packet. 加新狀態要同時改這兩段. 兩種做法:
   - 簡單: 用現有 `l2s` 的某個特殊值 (如 20001) 編碼"有氣泡" — 不改協議但污染語義, 不推薦
   - 正確: 加一個新狀態碼 `STATUS_BUBBLE=6`, 擴展或新建 packet 結構, 同步改上位機 — 推薦但成本高

5. **測試**
   - 先離線: 寫個 `tests/test_bubble_det.py` 加載若干張帶氣泡的 PNG, 斷言 `has_bubble=True`
   - 再集成: 設 `BUBBLE_DET_ENABLED=1` 跑 main.py, 看日誌有沒有 "氣泡 N 個"
   - 產品化: 把檢測頻率降到每 3 幀一次 (仿 `LIQ_DET_EVERY_N=3`), 避免阻塞主循環

6. **復盤** — 這種 pattern 適用於任何新檢測器:
   - 建模塊 (接口仿 li_det): `calibrate_X` + `detect_X` + 返回 dict
   - 加配置 (rt_config): 開關 + 閾值
   - 插 hook (detector._process_locked_mode): 首幀 calibrate, 後續幀 detect
   - 改協議 (control_channel, 可選): 新狀態碼 + 改發送 packet

### 9.2 MvImport 接口速查

從 R2 §3 整理. 直接在 Python 代碼裡用:

| 類/常量 | 位置 | 用法 |
|---|---|---|
| `MvCamera` | MvCameraControl_class | 核心類, 所有 API 都在它上面 |
| `MV_CC_DEVICE_INFO` | CameraParams_header | 設備信息結構體, 枚舉返回 |
| `MV_FRAME_OUT` | CameraParams_header | 取流返回的幀包 |
| `MV_CC_HB_DECODE_PARAM` | CameraParams_header | HB 海康自研格式解碼參數 |
| `MV_CC_PIXEL_CONVERT_PARAM_EX` | CameraParams_header | 像素格式轉換參數 |
| `PixelType_Gvsp_*` | PixelType_header | 像素格式常量 (Mono8, RGB8, Bayer...) |
| `MV_OK` / `MV_E_*` | MvErrorDefine_const | 錯誤碼 |

常用 API (都是 MvCamera 實例方法):
```python
cam.MV_CC_Initialize()                        # SDK 全局初始化
cam.MV_CC_EnumDevices(tlayerType, stDeviceList)   # 枚舉設備
cam.MV_CC_CreateHandle(stDeviceInfo)          # 創建句柄
cam.MV_CC_OpenDevice()                        # 打開設備
cam.MV_CC_GetOptimalPacketSize()              # GigE 最優包大小
cam.MV_CC_SetEnumValue("TriggerMode", 0)      # 關閉觸發模式
cam.MV_CC_SetEnumValue("ExposureAuto", 0)     # 關閉自動曝光
cam.MV_CC_SetFloatValue("ExposureTime", us)   # 設曝光
cam.MV_CC_StartGrabbing()                     # 開始取流
cam.MV_CC_GetImageBuffer(stOutFrame, 1000)    # 取一幀, 1000ms 超時
cam.MV_CC_FreeImageBuffer(stOutFrame)         # 釋放緩衝區
cam.MV_CC_StopGrabbing() / CloseDevice() / DestroyHandle()  # 清理
```

本倉庫 `camera_io.py` 已經把這些包好了, 99% 情況直接用 `OpenCamera()` / `GrabCameraFrame()` 就行.
