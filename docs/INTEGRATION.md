## 完整性证据

### ZIP 与外层源码

- 两个 ZIP 的全部条目通过 CRC 校验，归档结构可完整读取。
- 两版外层 46 个 Python 文件通过语法检查，无零字节源码文件。
- 外层比较：39 个文件完全相同、18 个同名文件变化，旧 `framework/image_sink.py` 被新 `framework/viz_recorder.py` 替换。
- v2 另有多层重复项目副本，最深 5 层；重复区域含 743 个文件，其中 197 个零字节文件。这些副本未覆盖外层源码，也未重复导入本仓库。

CRC 通过说明文件与 ZIP 记录一致，不能证明打包前文件未被截断。v2 的部分归档文件本身已不完整。

**v2 当前受跟踪源码完整。** 12 个损坏对象均为离线依赖 `.whl` 文件，每个压缩对象截为 524,288 字节；只有旧 `refs/remotes/origin/update` 引用受到影响，当前分支与 `main` 的历史不依赖这些坏对象。

## 整合内容

1. 以 v2 外层源码为基础，保留新版瓶型识别、曝光、液面检测、共享预处理、通信与会话录像流程。
2. 保留常见 8 位 Mono / RGB / BGR / Bayer 转换路径，补回其他格式的 SDK 转换和 HB 解压。底层彩色返回 RGB，由框架转换为 BGR。
3. 本地图像编码与 HTTP 开关分离：默认 HTTP 关闭时仍可记录本地会话。
4. 清理时保护当前、待转码及正在转码会话，收尾后重新执行保留策略；退出等待超时后取消后续转码并保留原始图像。会话标识增加微秒，避免短时间内重复使用同一目录。
5. 逐帧阶段耗时改为 `PIPELINE_TIMING=1` 可选诊断，默认关闭。
6. 新增标准 `requirements.txt`，旧 `requirments.txt` 保留兼容转发，补充安装、配置与测试说明。
7. 移除设备明文登录信息，X5 运维脚本使用环境变量与 SSH 密钥。原资料与原 Git 历史仅在仓库外保留，避免通过提交历史公开旧凭据。

相机修复保留 v2 的 GigE 设置和取图重试策略。快速像素转换不移除原生海康 SDK 依赖。

## 验证与限制

本机验证环境：Python **3.12.2**、NumPy **2.5.4**、OpenCV **5.0.0.93**、Matplotlib **3.11.2**。这些版本用于本地检查，不代表目标 ARM64 设备认证，也未写为依赖锁定要求。

统一无硬件测试入口：

```bash
python -m unittest discover -s tests/unit -v
```

本机 **28 项无硬件测试全部通过**，覆盖像素格式转换、SDK 回退 / HB 路径、HTTP 关闭时本地编码记录、会话保留与转码收尾，包括 3 项退出超时回归测试。测试使用模拟 SDK、合成帧、临时目录及模拟转码结果。历史联调脚本不属于该入口，可能连接网络、读取外部图片或真实操作相机。

GitHub Actions 配置在推送与拉取请求时使用 Python 3.10 / 3.12 执行源码编译和无硬件测试；远程通过状态以 Actions 实际结果为准。

本次未进行真实海康相机采集、RDK X5 长时间运行、真实上位机联动、目标设备 `ffmpeg` 编码或定容精度验收。归档校验、源码检查和模拟测试不能证明这些结果；旧注释中的性能数字也不作为本次结论。
